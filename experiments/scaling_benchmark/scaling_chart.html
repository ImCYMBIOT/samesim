Scaling Benchmark

Wall-clock time vs. agent count

Same gossip experiment (50 fixed ticks, no early stopping), single run per point. ErdosRenyiTopology was O(n²) as of the first pass of this benchmark (checked every possible agent pair regardless of density) — fixed to O(n+m) using the Batagelj–Brandes direct-edge-sampling algorithm. Both topologies now run the full n=100–100,000 range.

Ring local slope 0.96–1.13 throughout
Erdős–Rényi (avg degree 8) local slope 0.98–1.25
Single run per point (this benchmark measures raw compute cost, not stochastic behavior — see the topology validation study for seed-averaged statistics). Both topologies now stay within local slope ~1–1.25 across the full range — no more runaway quadratic growth. Erdős–Rényi is still consistently ~2× slower than Ring at matched n despite virtually identical event counts (9.78M vs 9.80M at n=100,000); profiling (cProfile) traced this specifically to GossipBehavior.step()'s own execution time, not the engine — event dispatch, heap operations, and metrics costs are nearly identical between the two. Most plausible cause: larger, more variable neighbor and inbox lists at average degree 8 vs. Ring's fixed degree 2 — not yet isolated further.
