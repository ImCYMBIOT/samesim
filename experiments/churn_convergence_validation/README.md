# Gossip convergence under churn

The Phase 3 validation target of [docs/design.md](../../docs/design.md): does
gossip convergence degrade gracefully as agents fail and recover more often,
or is there a cliff?

**Answer: among running agents, gracefully.** Convergence time grows as a
smooth power of the fraction of agents that are up, with no threshold; with
half the agents down it takes about 3–3.5× longer. **Agreement across
*every* agent, crashed ones included, is a different quantity.** With long
outages it is dominated by how long the agents that crashed early stay
down, not by the churn rate.

## Setup

- Push gossip (`GossipBehavior`, fan-out 2), synchronous, lossless
  `GossipProtocol`. Erdős–Rényi, n = 200, average degree 8. 400 ticks.
- `RandomChurn`: each running agent fails at rate λ, each failed one
  recovers at rate μ = 1/D. Long-run down fraction f = λ/(λ+μ).
- f ∈ {0, 0.01, 0.02, 0.05, 0.1, 0.2, 0.3, 0.5}, mean downtime D ∈ {5, 50}
  ticks, **40 seeds each: 600 runs.** f = 0 is a single shared baseline.
- A crashed agent keeps its value and rejoins with it
  (see the [User Guide](../../docs/user_guide.md#6-churn-failures-recoveries-joins-rewiring)).

Measured with `ConsensusMetric`, added for this study:

| Series | Meaning |
|---|---|
| running variance | variance of `value` among agents that are up |
| all variance | variance among all agents, crashed ones at their frozen value |
| drift | consensus mean minus the true initial mean, in units of the initial σ |

Times are the first tick a variance falls to 10⁻⁴ of its initial value:
medians over seeds with bootstrap 95% CIs. One baseline graph (seed 15)
has an isolated agent and never reaches 10⁻⁴ under any setting; it is
excluded and counted as censored in `summary.txt`.

## Results

Generated by `python analyze.py` (full output in [`summary.txt`](summary.txt)).

### Running agents: graceful

| f | D = 5: t(10⁻⁴) | slowdown | D = 50: t(10⁻⁴) | slowdown |
|---:|---:|---:|---:|---:|
| 0 | 27 (26–29) | 1.00 | 27 (26–29) | 1.00 |
| 0.05 | 31 (29–32) | 1.15 | 27 (27–31) | 1.00 |
| 0.1 | 33 (31–36) | 1.22 | 28 (26.5–32) | 1.04 |
| 0.2 | 42 (39–45) | 1.56 | 30.5 (27–36) | 1.13 |
| 0.3 | 50.5 (48–55) | 1.87 | 33 (30–38.5) | 1.22 |
| 0.5 | 95.5 (92.5–103) | 3.54 | 80.5 (54–108.5) | 2.98 |

Fitted: t ∝ (1 − f)^−1.81 for D = 5 and (1 − f)^−1.47 for D = 50. No cliff
anywhere in the range: at every churn level the running agents converge.

**Short outages cost the running agents more than long ones** at the same
down fraction, with non-overlapping CIs from f = 0.2 to 0.3. With D = 5
the set of running agents turns over fast: agents keep dropping out
mid-exchange and rejoining with values from a few ticks ago. With D = 50
the same fraction is down, but it is a more stable subset, and the running
agents behave like a smaller, slightly sparser network.

### All agents: set by downtime, not churn rate

| f | D = 5: t(10⁻⁴) | D = 50: t(10⁻⁴) |
|---:|---:|---:|
| 0 | 27 (26–31) | 27 (26–31) |
| 0.05 | 31 (30–34) | 36 (31–47) |
| 0.1 | 36 (34–40) | 61 (47–72) |
| 0.2 | 46 (41–48) | 98 (86–135) |
| 0.3 | 59 (54–66) | 155 (130–180) |
| 0.5 | 116 (104–125) | 236 (227–264) |

With D = 50 and f = 0.1, the running agents agree by tick 28, but the whole
system takes until tick 61.

**Why.** An agent that crashes while values are still spread out keeps a
value far from the eventual consensus. One such agent is enough to hold
the all-agent variance above 10⁻⁴ of its initial value, since a single
value off by σ₀ contributes σ₀²/200 = 5×10⁻³ of the initial variance.
Agents that crash later hold values already close to consensus. So
whole-system agreement waits for the early crashes to come back, and long
outages make that wait long.

**A simple model of this gets the trend, not the numbers.**
`analyze.py`'s `stale_model` treats every crash before t* = 10 ticks (the
churn-free time to 10⁻² of the initial variance, not fitted) as a
far-off stale value, and waits for the last one to recover. Against the
40-seed CIs it overpredicts at f = 0.05–0.2 (e.g. 99 vs 61 at f = 0.1) and
underpredicts at f = 0.5 (205 vs 236). The overprediction is expected from
the model's simplification: values crashing before t* have already
partly mixed, so not every early crash holds the variance above
threshold. At f = 0.5 the running network itself is slow, which the model
ignores.

**Correction.** An earlier version of this study (10 seeds per point, and
Simul8's old `seed XOR agent_id` seeding, which made runs with different
seeds partly copies of each other; see
[external_validation/](../external_validation/README.md)) reported this
model as matching "within 10% up to f = 0.2". At 40 independent seeds it
doesn't. The earlier agreement was within the noise of 10 correlated
seeds. The same re-run moved the running-agent exponents from −1.48 and
−1.00 to −1.81 and −1.47.

Once the all-agent variance falls below 10⁻⁴ it stays there in 570 of 600
runs: churn after convergence reinjects values that are already close.

### Accuracy: churn doesn't bias the consensus

Median |drift| is 0.018σ₀ without churn (95% CI 0.014–0.024), and every
churn setting's CI overlaps it (medians 0.016–0.029σ₀). Push gossip isn't
mass-conserving (an agent averages its own value with whatever arrives),
so the consensus drifts slightly from the true mean even without churn.
Churn doesn't measurably add to it.

### Lost messages match the closed form

Each tick, (1 − f)·n agents each send k = 2 messages, and a fraction f go
to crashed agents, so about f(1 − f)·n·k·T are lost over T ticks. Using the
observed time-averaged f, the median count matches within 2.5% in every
cell. The observed f is below target for D = 50 because `RandomChurn`
starts with every agent up and takes about D ticks to reach its stationary
fraction.

## Limits

- One graph family and size (Erdős–Rényi, n = 200), one protocol (push
  gossip). Pairwise asynchronous gossip conserves the sum and may behave
  differently, especially for drift.
- Exponential downtimes only. If the stale-value explanation is right,
  heavier-tailed downtimes should slow whole-system agreement much more
  than running-agent agreement. That is a direct test of it, not yet run.
- The stale-value model is qualitative. A quantitative version would need
  the distribution of how far an agent's value is from consensus at the
  time it crashes.
- Crashed agents keep their state. Agents that restart from a fresh value
  would be a different, harder case.
